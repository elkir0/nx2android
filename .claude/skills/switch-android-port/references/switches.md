# Host and backend switches (Android)

**How to set them:**
- **Start-up switches:** put them in the app's `env.txt` (`/sdcard/Android/data/<package>/files/env.txt`, one `KEY=VALUE` per line), then restart the app.
- **Live switches:** append `env KEY=VALUE` to `ctl.txt` while the game runs. These are re-read at each submission or present. `ctl.txt` needs a development build with `DM_CTL=<files>/ctl.txt` in `env.txt`; release builds ignore it.

The source of each switch is in `nxnative/dm/android/` unless noted. Check the code comment there before relying on a description below: switches are added and retired as bugs are found.

## Diagnostics

| Switch | When read | What it does |
|---|---|---|
| `DM_VK_VALIDATE=1` | start-up | Khronos validation layer; its messages go to the log. The APK must carry it (`mkapk.py --extra-so <libVkLayer_khronos_validation.so>`; built copy in `tools/vvl`) |
| `DM_VK_SHOTS=N` | live | save each of the next N presented frames as `frame_<n>.ppm` in the files folder (logs "frame shots: presents a to b") |
| `DM_VK_SHOT=n1,n2` | start-up | headless runs: save those presents (`DM_VK_SHOT_DIR`) |
| `DM_VK_PASSDUMP=1` / `=N` | live | dump each pass's first colour target and its depth (PPM, NaN counts, depth stretched) for one frame; `=N` waits N−1 presents first. **The dump adds barriers and depth reads, which can hide bugs** |
| `DM_VK_TRACE_PASS=-2` / `=n` | live | `-2` lists one submission's passes; `n` logs every draw of pass n once (targets, depth target, textures, pipeline state); the `-2` list also shows each barrier's NVN bits and where each pass was ended from (an offset in `libdmhost.so`), each dispatch's storage buffers (`s<n> <address>+<size>`, for a DM_CTL `memdump`) and the buffer copies, clears and uniform updates by address. DM_CTL `peek <address> <count>` / `memdump <address> <bytes> <path>` read guest memory, zero-copy pool pages too (Pokémon Legends: Z-A's culling counters were found that way) |
| `DM_VK_TRACE_SIZE=WxH[:fmt[:fmt]][#n]` | live | trace the (n+1)th pass whose first colour target has that size (and formats): pass numbers move by tens from frame to frame |
| `DM_VK_TRACE_FRAME=WxH[:fmt[:fmt]]` | live, one submission | trace every pass of the next submission whose targets match (a whole effect chain in one log); trace lines also describe each sampler (wrap, filters, LOD, border) |
| `DM_VK_PASSDUMP_SKIP=n` / `=WxH`, `DM_VK_PASSDUMP_SIZE=WxH[,WxH]` | read when a dump starts | skip the first n passes, or start at the first pass of that size (depth included); only passes of those sizes (colour only) |
| `DM_VK_PASSDUMP_FRAMES=N` | read when a dump starts | keep dumping for N presents in a row (up to 96 dumps; the log names each dump's present): with `DM_VK_PASSDUMP_SIZE`, catches an effect that is wrong in single frames |
| `DM_VK_PASSDUMP_PASS=n[,n...]` / `DM_VK_PASSDUMP_FMT=a/b` | live | only these pass numbers of each submission / only passes whose first two colour formats are VkFormat a and b (pass numbers move from frame to frame; TTYD's first lit pass is `122/64`), to follow one pass over many frames |
| `DM_VK_PASSDUMP` formats | (with a dump) | RG16F targets (velocity fields) are written as red/green around grey, nonzero texels marked blue, plus the raw values in `<dump>.f32`; float targets log their HDR mean beside min and max; an R11G11B10 target of 4 texels or fewer logs every texel (exposure values) |
| `DM_VK_LOG_FS=<fragment shader key>` | live | one line per draw with that fragment shader (present, pass, depth state, viewport), and its samplers as the draw sees them (`DM_VK_SAMP_LOG` explains why one changed) |
| `DM_VK_SAMP_LOG=n` | live | log the next n sampler registrations (ID, LOD range, present, thread) and each submission's start, in time order with the replay's lines |
| `DM_VK_PASSDUMP_DEPTH=1` | read at each pass | with `DM_VK_PASSDUMP_SIZE`, the size-filtered passes' depth too; every depth dump also writes its raw values as float32 (`<name>.f32` beside the PPM) |
| `DM_VK_TEXDUMP=<pool hex>+<offset hex>` | read when a dump starts | during the dump, the first sampled image at that pool offset (the trace prints both) is blitted to RGBA16F and dumped with the passes (level 0, up to 6 layers, pass number −100 − layer): a compressed texture such as a BC6H cube map, decoded by the GPU |
| `DM_VK_TEXDUMP_LEVEL=n` | read when the texture dump is written | with `DM_VK_TEXDUMP`: that mip level instead of level 0 (past the image's last level: the last) |
| `DM_VK_PASSDUMP_TARGET=n` | read at each dumped pass | dump colour target n (0-7) where the pass has one, instead of the first one bound |
| `DM_NVN_SHDUMP=1` (any value) | read once, at the first shader missing from the bundle (`gfx_vk_exec.c` `shader_dump`; `gfx/nvn/hle_nvn.c` then keeps each program's control sections) | each shader missing from the bundle is written to `<files>/shader_<key>.bin`, its 0x880-byte control section followed by its code area, to look for it in the game files (Xenoblade Chronicles 3's title had one such program) |
| `DM_VK_NOPCACHE=1` | start-up (`gfx_vk_core.c`) | start with an empty Vulkan pipeline cache (the saved one is ignored; app-owned files cannot be deleted over adb) |
| `DM_VK_WATCH=<pool offset hex>[#n]` | live | log the next n uses of images at that pool offset (attachment, sampled, copy) with present and pass numbers: who writes what a pass reads |
| `DM_VK_UBO_LOG=<shader key hex>[#n]` | live | log the next n uniform buffers that shader reads (every word up to 512 bytes, a hash; for register 0 of a vertex shader also its vertex stream 0; for an indexed draw, the index data's hash and range, every word of the first vertex the draw reads, and once per index data every index and vertex). Use with `DM_VK_X_NOSETC=1`, or reused descriptor sets hide draws. With a primitive-ID fragment shader through `DM_VK_SPV_ALT` it shows which triangles a draw lost (XC3's cloud dome) |
| `DM_VK_SPV_DIR=<dir>` (start-up) + `DM_VK_SPV_ALT=1` (live) | | pipelines made while `ALT` is on use `<dir>/<key>.spv` in place of the bundle's code where the file exists (same bindings), so two compilations of a shader compare in one run (e.g. the translator's GLSL through `glslc`, or a patched module) |
| `DM_VK_SPV_ALT=1` in env.txt (start-up, with `DM_VK_SPV_DIR`) | | compute shaders take the alternative code too (they are all built at the first submission and kept) |
| `DM_VK_X_CSALT=<n>[:<m>:<r>]` (with `DM_VK_SPV_DIR`, `DM_VK_SPV_DIR2` at start-up) | live | compute pipelines made from then on take the bundle's code (`0`), `DM_VK_SPV_DIR`'s (`1`) or `DM_VK_SPV_DIR2`'s (`2`) where the file exists; with `m`, only shaders whose key mod `m` is `r` (bisect which shaders a change needs). Each choice's pipelines are kept apart, so switching back costs nothing. Two translations compare in the same scene, which a restart cannot promise: Mario Kart World's Free Roam starts at another place each time |
| `DM_VK_X_CSSERIAL=1[:<m>:<r>]` | live | (with `m`: only shaders whose key mod `m` is `r`) every dispatch of at most 4096 workgroups runs one workgroup at a time, in order, a compute-to-compute barrier between them (an indirect one only when its counts are the CPU's): whether an artifact comes from workgroups that run together or out of order on the device. Very slow |
| `DM_VK_X_SPILL_CPUIND=0` | live | a compute shader with its shared memory in a buffer, dispatched indirect, always takes its group counts from the GPU (one dispatch, `[RED]` 158), never from the CPU's copy of them, which `vk_gpu_pending` may wrongly take as current (it does not see global-memory stores through a pointer nor graphics stages' storage writes) |
| `DM_VK_PASS_TIMES=1` | start-up | GPU timestamps around every pass: the GPU profile (`DM_VK_GPUPROF`) from the first frame, whose lines every `DM_VK_GPUPROF_FRAMES` presents (300) list the costliest passes. Disturbs Adreno's binning: compare runs only |
| `DM_VK_PASS_TIMES=1` dispatches | start-up | compute dispatches are timed in the stretches between passes (a stretch's dispatches, copies, clears and barriers in the list), up to 512 units a submission |
| `DM_VK_GPUPROF=1` / `=N` | live (read at each submission's start, `gfx_vk_core.c` `prof_wanted`) | GPU profile, off by default, where the device has timestamps: each submission's main command buffers are cut into units (a pass, or the stretch between two passes: dispatches, copies, clears, uniform landings, LRZ touches, barriers) with a timestamp at each boundary; every `DM_VK_GPUPROF_FRAMES` presents two lines give the totals by kind and the 15 costliest passes and 5 costliest stretches. `=N` over 1 also sets that period. The timestamps cost time and disturb Adreno's binning: compare runs with the profile on |
| `DM_VK_GPUPROF_FRAMES=N` | live | the GPU profile's period in presents (default 300) |
| `DM_VK_PASS_SPIKE=<ms>` | start-up (with `DM_VK_PASS_TIMES=1`; default 25) | a frame whose timed passes and dispatches, or whose submissions, take longer logs `GPU spike:` with its six costliest items and the time outside them. The timestamps themselves add time: Tears of the Kingdom's 18 ms frames summed to 26 ms of passes, so set it well above the normal sum |
| `DM_SLOWFRAME=1` | start-up (`gfx/nvn/hle_nvn.c`) | one `[slowframe]` line per dropped frame with a breakdown (frame, work, NVN, wait, thread and process CPU) |
| `DM_VK_LOG_UPLOADS=1` | at each packaged upload (`gfx_vk_tex.c`; 60 lines at most) | which packaged textures are uploaded or re-uploaded |
| `DM_VK_SKIP_OPS`, `DM_VK_DBG_DRAW` | start-up | bisection aids: skip command kinds; 1 no draw calls, 2 no vertex buffers, 4 no descriptor sets |
| `DM_VK_NOCULL=1` | start-up | no face culling (test for winding bugs) |
| `DM_VK_PROF=1` / `=2` | live, arms once (`gfx_vk_exec.c`) | sampling profiler of the replay thread (1 ms of its CPU time): every 20 s the most frequent places, as offsets in `libdmhost.so` (`=1` charges libc and driver time to our first caller, shown `via:`; `=2` shows the place itself). Resolve with `llvm-symbolizer --obj=<build>/android/host-debug/libdmhost.so 0x<offset>`  **Xenoblade Chronicles 3 crashed in its own data code while loading a save in 2 of 2 runs with it on from start-up (0 of 4 without): arm it after loading** |
| `DM_VK_PROF_TID=<tid>`, `DM_VK_PROF_OUT=<file>` | read when `DM_VK_PROF` arms | sample that thread of the process instead of the replay thread, and append the raw samples (leaf pc, lr, six frame-chain returns) to the file. **Host threads only: sampling Xenoblade Chronicles 3's render thread crashed the game in its own code** (use `DM_NVN_ASYNC=1` to profile the replay on a host thread) |
| `DM_VK_CRUMBS=1` | start-up (`gfx_vk_exec.c`) | for a device lost (GPU hang): each pass end and dispatch writes its number into host-visible memory after a full barrier; when the device is lost the log names the last work the GPU finished and the passes after it, with their shaders. Slows the GPU |
| `[timeline]` lines | with `DM_NVN_ASYNC=1` (`gfx/nvn/hle_nvn.c`) | per frame: the game's gap between a sync wait and its next submission, queue delay, replay, and the GPU's tail after the replay |
| `DM_NVN_SEQ=N` | live (`gfx/nvn/hle_nvn.c`) | the next N frames' submissions, fences, acquires, sync waits (with the time waited) and presents, in order, with thread and time: what the render thread waits for |
| `DM_NVN_X_SYNCPOLL=<ms>` | live (`gfx/nvn/hle_nvn.c`, read every 200 ms) | a SyncWait of under 1 ms (a poll) on GPU work not done yet waits up to that long instead; such polls are counted in `[nvn] SyncWait polls` lines either way (a game that leaves out work whose GPU results it finds not ready). Mario Kart World makes none |

## Behaviour toggles (for A/B; defaults are the fixes)

| Switch | When read | Default and meaning |
|---|---|---|
| `DM_VK_CB_DRAWS=N` | live | split the frame into command buffers every N draws (128), only before passes with a new depth image; `0` = never |
| `DM_VK_SUBMIT_SPLIT=0` | live | don't submit the pieces early |
| `DM_VK_X_CUTANY=1` | live | cut before any pass (the old rule that caused LRZ flicker) |
| `DM_VK_PASS_SPLIT=n` | live (0 = off, the default) | a pass is ended after every n of its draws and begun again on the same attachments (every load op LOAD), with a cut before it, so its first parts reach the GPU while the replay records the rest (`DM_VK_CB_DRAWS` cuts only between passes, and Unicorn Overlord's battle map draws ~2,030 of its ~3,546 draws in one pass). Not inside a run of rasterizer-discard draws, and only passes without depth. The discards' store look-ahead is off while it is on |
| `DM_VK_PASS_SPLIT_DEPTH=1` | live (A/B) | with `DM_VK_PASS_SPLIT`: passes with depth are split too, with a depth texel written back (LRZ touch) before the second part (a pass that goes on with a depth buffer begun in an earlier command buffer meets Adreno's stale LRZ) |
| `DM_VK_X_NOGS=1` | live | leave out draws with a geometry shader (A/B their GPU cost: Xenoblade Chronicles 3's effects, 0.7 ms of 22 in a battle) |
| `DM_VK_LRZ_TOUCH=0` | live | drop the LRZ touches: the one-texel depth read before passes that load a depth-stencil buffer (brings NEO's menu-wipe flicker back) the texel written back into the depth buffer a pass switches away from (brings XC3's cloud-layer drop-outs back), and the texel written back into a depth buffer a pass goes on with after a command-buffer cut (brings Hades II's one-frame light drop-outs back) |
| `DM_VK_FDZ=0` | live | no fragment-depth variants: draws that test a depth buffer a fragment shader wrote through `gl_FragDepth` (in the last two presents) normally get a variant of their fragment shader that writes `gl_FragDepth = gl_FragCoord.z`, the same depth tested after the shader, out of Adreno's early culling, which dropped whole triangles of Hades II's lights (they went out in turn every 24-48 frames) |
| `DM_VK_FLIPY=0` | live | the old clip-space y convention (pictures flip) |
| `DM_VK_DISCARD=1` | live | NVN's discards (DiscardColor / DiscardDepthStencil), which on a tiler save the loads and stores of tile memory: `1` (default) depth / stencil discards become DONT_CARE loads and stores, `2` colour ones too, `0` none. Colour is not the default: a game that draws over part of a colour target it discarded and shows the rest would show tile garbage where the console kept the old pixels |
| `DM_VK_X_NOBAR`, `DM_VK_X_DEPTH`, `DM_VK_X_COLOR` | live | cost measurements that **draw wrong**: no barrier before a pass; depth neither loaded nor stored; colour not loaded unless cleared |
| `DM_VK_X_NODISPBAR=1` | live | cost measurement that may draw wrong: no barrier after compute dispatches (Tears of the Kingdom: no GPU change at about 23 dispatches a frame) |
| `DM_VK_SPILL_SPLIT=0` | live | a dispatch of a compute shader whose shared memory is in a buffer (Mario Kart World's 48 KB shaders), with more workgroups than the buffer's slices, is one dispatch, as `nvn_mtl.m` does: the A/B of the parts' cost. Default: cut into parts (`vkCmdDispatchBase`) with a barrier between them, so no two workgroups share a slice at once. An indirect dispatch whose counts the GPU writes cannot be cut (`[RED]` once) |
| `DM_VK_BAR_MERGE=0` | live (`gfx_vk_dq.c`) | every full barrier recorded (default: one recorded right after another, with only binds, dynamic state and push constants between, adds no dependency and is left out; the replay makes such runs around dispatches, 158 a frame in Mario Kart World's races). An entry point the merge does not know turns it off for good |
| `DM_VK_X_NOSETC`, `DM_VK_X_NODRVC`, `DM_VK_X_LANDCUT`, `DM_VK_X_NOKEEP`, `DM_VK_X_NOSHC` | live | flicker experiments: no descriptor-set reuse; no driver-segment reuse; deferred uniform updates land at each cut; no pass kept for repeated targets; no uniform-shadow reuse |
| `DM_VK_X_NOSETMEMO=1`, `DM_VK_X_SETVERIFY=1` | live | the per-stage set memo (within a submission, a stage's last set is used again when only its constant buffers' offsets changed): `NOSETMEMO` turns it off (A/B); `SETVERIFY` collects one memo hit in 64 anyway and compares, `[RED]` on a difference |
| `DM_VK_DYN_UBO=0` | start-up | no dynamic uniform-buffer offsets (descriptor reuse drops) |
| `DM_VK_SET_KEEP=0` | live | each submission's own descriptor sets, as before. Default: a set whose every descriptor outlives the submission is made from kept pools and found again by its content in later submissions (Mario Kart World's race frame made ~1,370 new sets, 4.3 ms, 99% of them an earlier submission's content); all are dropped when a view or an image goes, a pool comes or goes, or the kept pools are full |
| `DM_VK_KEEP_FINE=0` | live | kept sets are dropped at any pool or view change, as before. Default: only for a freed object a kept set may name (a pool gone, the views of an image one names); Mario Kart World's free roam had 5,403 flushes a minute the old way, the replay's descriptor sets 12 ms a frame |
| `DM_VK_TVC_KEEP=0` | live | texture views by ID kept for one submission. Default: kept across submissions while the ID is not registered again with another texture and no image or view went (Mario Kart World's race frame, 4 submissions of ~2,600 textures: ~3,600 views a frame looked up again, ~17% of the replay thread, kept for one). Not for storage images, nor under `DM_NVN_ASYNC` |
| `DM_VK_CBUF_CACHE=0` | live | each constant buffer's descriptor looked up at every draw. Default: the last descriptor each stage's uniform slot gave is used again for the same address and size while no pool came or went and no deferred update changed it (Mario Kart World's race: ~9,700 lookups a frame) |
| `DM_VK_DRV_INPUTS=0` | live (read every 256 driver segments) | a stage's driver segment (c0) found by its bytes. Default: kept while its inputs are the same (storage buffer table; base instance, or dispatch size and uniform table) and looked up by them: building and hashing its 2 KB was ~7% of the replay thread |
| `DM_VK_PROG_CACHE=0` | start-up | a program bind's shaders looked up at every bind. Default: cached by program, serial and stage mask (the lookups took 5% of the replay thread at Mario Kart World's ~800 binds a frame) |
| `DM_VK_REG_SAME=0` | start-up (`gfx_vk_tex.c`) | every texture registration counts as a change. Default: the same registration again (the same texture object and view at the ID it holds: an engine refreshing its table, Mario Kart World ~87 a frame in a race) changes nothing and drops nothing kept by registration (views by ID, the set memo) |
| `DM_VK_SETSPLIT=1` | live | off by default: under the same pipeline layout, only the run of sets whose handle or dynamic offsets changed is bound again (Adreno's `vkCmdBindDescriptorSets` took ~22% of the replay thread on Unicorn Overlord's battle map) |
| `DM_VK_NOPREWARM=1` | start-up | no pipeline prewarm, and no compute pipelines made ahead at the first submission |
| `DM_VK_COMPUTE_WARM_MAX=N` | start-up (default 256) | the most compute pipelines made ahead at the first submission: a bundle with more compute shaders gets none made ahead (Monster Hunter Rise's 4,096 or more held ~550 MB more, and a Retroid Pocket 5 ran out of GPU memory loading the first area) |
| `DM_VK_PREFETCH=0` | start-up | a new program's shaders are made at its first draw, as before. Default: their modules, set layouts and reflection are made on a background thread when the game sets them (SetShaders) |
| `DM_VK_ASYNC_PIPE=0` | live | every new graphics pipeline is built on the replay thread, as before (default: a draw whose pipeline is new goes to 2 background threads and is left out until it is built, when every target of its pass, as an image, was drawn in this present and the 2 before it, and none is a linear render target; Super Mario Odyssey's first cap throws went from 6 frames over 50 ms to 0). Looser rules lost SMO's coin counter, tutorial movie or fog for the whole run: targets aged by size and format, presents counted with gaps (an image kept from the title, drawn once at the load), the fog's CPU-read wave targets |
| `DM_VK_PROF_SLOW=1` | live | a submission whose replay took over 40 ms logs `slow replay`: pipelines built on the replay thread, textures, pools sync, shader modules, binds, descriptor sets, cuts, compute pipelines; plus `pipeline built here: attachment …` for each pipeline a young target kept off the background threads (first 300) |
| `DM_VK_UBWC=3` | start-up (`gfx_vk_tex.c`) | default 3 (bits): 1, colour images get a format list (their format and its sRGB twin) instead of MUTABLE_FORMAT; 2, depth images neither MUTABLE_FORMAT nor EXTENDED_USAGE. Adreno then keeps its UBWC compression: Super Mario Bros. Wonder's world map 11.8 → 8.7-8.9 ms of GPU (9.5-10.0 with 1 alone), Unicorn Overlord 35-40% less on the Adreno 730. A colour view in another format falls back to the image's own and logs `[RED] view format … of a format-listed image`: such a game wants `2` (or `0`) in its profile |
| `DM_VK_IMAGE_SHARE=0` | start-up (`gfx_vk_tex.c`) | two NVN textures over the same storage that differ only by `IMAGE` are two Vulkan images again, as before (default 1: one image; `IMAGE` is left out of a colour texture's image key, as it already was for depth and stencil). With sharing on, a texture with `IMAGE` that finds an image made without storage use has it made again with that use and its content copied (`texture … its image made again with storage use`, the first 8, then a count every 64). Where that cannot be done (sparse or dense, packaged or CPU content, an sRGB / linear twin's image, linear, multisampled, a format without storage images, or an image this submission's command buffers already wrote) it gets an image of its own and logs `[RED] … a second image beside the one without IMAGE … (reasons)`: what one writes the other does not see. A sparse pool's textures keep `IMAGE` in their key either way |
| `DM_VK_SYNC_PRESENT=1` | start-up | present on the game thread instead of the present thread |
| `DM_NVN_ASYNC=1` | start-up (`gfx/nvn/hle_nvn.c`) | asynchronous replay: submissions and presents run on a replay thread, syncs wait for the job's replay and then its GPU fence. Xenoblade Chronicles 3 has it in its profile (`env`): the replay (~26 ms a frame in Resolution-mode battles) overlaps the game's render thread; the window acquire then waits for every job queued so far to be replayed (`DM_NVN_ACQ_REPLAYED`), and texture registrations are seen by each job as they were when it was queued (`gfx_vk_tex.c`). Off by default; `[timeline]` lines show the frame |
| `DM_VK_MT_REPLAY=1` | start-up (`android/gfx_vk_dq.c`); `porter port --mt-replay` (the GUI's Multithread replay box) writes it to env.txt | two-stage replay: the vkCmd* calls (40 of them) are copied into a 32 MB ring and a "vk record" thread makes the real calls in order; the calls that end, submit or present a command buffer (and pool resets, waits) wait for the ring to empty first; a call with a pNext the copy does not know runs directly after that wait. Tears of the Kingdom at the Great Sky Island pond: replay 11 -> 7.6 ms a frame, frames held at 60 p50 19.85 -> 16.69 ms; the same 11 validation-layer message kinds with and without it, none about threads. A drain that waits over 1 s logs a `[RED]` line. Off by default |
| `DM_VK_DRIVER=<library>` | start-up (`android/gfx_vk_core.c` vk_init) | a Vulkan driver the APK carries (Mesa's Turnip; `porter port --vulkan-driver`), loaded through libadrenotools (`libadrenotools.so` and its hooks `libhook_impl.so`, `libmain_hook.so`, `libfile_redirect_hook.so`, `libgsl_alloc_hook.so` beside it in the APK's extracted libraries): a second copy of the system loader whose driver is this library, so the surface and swapchain stay the loader's. A driver that does not load or offers no Vulkan 1.3 GPU logs `[RED]` and the system's driver runs. TotK on the Y700 with Turnip 26.2.6 (tools/turnip/build.sh): correct picture; open-world replay ~2.6 us a draw against ~6.1 on Qualcomm's driver |
| `DM_GPU_TURBO=1` / `=0` | live (`android/perf_android.c` gpu_turbo, every 60 presents) | Adreno's GPU at its highest clock: KGSL power control off on `/dev/kgsl-3d0` (the property libadrenotools' `adrenotools_set_turbo` sets), for any driver on KGSL; `=0` gives the GPU its own clock control back. Logs whether the kernel took it. Tears of the Kingdom on Turnip: a shrine 18 -> 15 ms of GPU and 60 fps held; the open world 30 -> 60 fps with some drops, the GPU 53 -> 75 °C in 60 s |
| `DM_VK_PERF_HINT=max\|min\|scaled:N\|default` | live (read at each submission, set only when it changes; `gfx_vk_core.c`) | a GPU clock hint through `VK_QCOM_queue_perf_hint`, where the device has it (the log says so at start-up): `max` the highest clock, `min`, `scaled:N` (scale N in the driver's unit, 100 without `:N`), `default` the driver's own governor again; `2`, `1` and `3` are max, min and scaled. Unset: never asked (off by default). An A/B against `DM_GPU_TURBO`: Mario Kart World switches its present interval between 1 and 2 about 1,400 times a race, and the governor kept the clock low |
| `DM_NVN_ACQ_REPLAYED=0` | start-up (`gfx/nvn/hle_nvn.c`) | with `DM_NVN_ASYNC=1`: the window acquire does not wait for the queued jobs' replay. XC3 then drew whole-screen garbage (solid colours, smears) while the camera turned in about half of the recordings; with the wait at the next submission instead, 2 of 6 |
| `DM_VK_X_NOPRERESET=1` | start-up (`gfx_vk_core.c`) | a submission slot's command buffers are reset as they are begun again, on the replay thread, instead of on the completion thread when its submission is done |
| `DM_VK_X_FENCES=1` | start-up (`gfx_vk_core.c`) | submissions signal a ring of fences instead of a timeline semaphore, as on a Vulkan 1.1 driver without timeline semaphores (the Adreno 618 / 619 of 2021, issue #15). On the Y700 it cost nothing measurable in Super Mario Bros. Wonder's level 1 |
| `DM_VK_X_BC_CPU=1` | start-up (`gfx_vk_core.c`) | BC textures decoded on the CPU into uncompressed images (`gfx_vk_tex.c` `bc_decode`), as on a driver without `textureCompressionBC`. With `DM_VK_X_FENCES=1` the Y700 stands in for those phones; Wonder's level 1: about 1 more dropped frame in 300, ~100 MiB more memory |

| `DM_VK_TS_CAL=1` | live | counter timestamps from the GPU's clock plus one offset (the least late completion of the last 256 submissions), not each from the completion thread's clock less the GPU time to its submission's end: reports of two submissions no longer disagree by that thread's lateness (milliseconds) |

| `DM_VK_IND_C0=0` | live | an indirect dispatch's group counts are not copied into c0 + 0x200 before it (on by default, as `nvn_mtl.m` does): the shader reads 0 there, as before |

| `DM_VK_XFB=0` | live | no transform feedback captured (A/B). Default: each capturing draw is a Vulkan capture of its own (Xenoblade Chronicles 3 steps its GPU particles this way) |
| `DM_VK_MESH=0` | start-up (`gfx_vk_core.c`) and live | at start-up: `VK_EXT_mesh_shader` stays off and every DrawMeshTasks is skipped; live (each submission): the DrawMeshTasks draws are left out. | `DM_VK_ALPHA=0` | live | draws without the alpha-test variant, as before it came (alpha-tested pixels are then kept) |
| `DM_VK_FIRST_STORE=0` | live | cost measurement that **draws wrong**: the first-invocation stores the replay makes before a dispatch are left out (the translator took them out of the shaders, so the lists they reset are not reset) |

## Memory

| Switch | When read | What it does |
|---|---|---|
| `DM_VK_MEMLOG=<s>` | start-up (`gfx_vk_core.c`) | at most every s seconds: the memory line (pools, images and their blocks, sparse tiles and address space, scratch, VmRSS / RssAnon / VmSwap, kgsl, MemAvailable, SwapFree) and two census lines (`gfx_vk_tex.c` `vk_tex_census`): textures uploaded from guest memory and what of their storage the shadow file could hold; the GPU's images never written; images not looked up for a minute; images' memory against their NVN storage; resolution families (one pool offset, one format, several sizes) and the memory one allocation each would leave over; sparse places against the physical tiles behind them; the shaders' SPIR-V kept; then a shaders' line (`gfx_vk_shader.c` `vk_shader_mem`): SPIR-V kept and dropped, and the variants that rebuilt it from the bundle (`DM_VK_SPV_KEEP`) |
| `DM_VK_SMAPS=<s>` | start-up (`gfx_vk_budget.c`) | every s seconds, on a thread of its own: `/proc/self/smaps` summed by what each mapping is (guest heap, alias and stack regions, the shadow file, game modules, kgsl, dma-bufs, shader bundle, RomFS image, host malloc, thread stacks, libraries, the rest; resident and swapped) and the count of mappings (limit 65,530) |
| `DM_VK_SHADOW=1` | start-up (`gfx_vk_shadow.c`; off by default until measured) | the guest pages of uploaded textures (and the physical pages behind uploaded sparse tiles) written to an unlinked file in `$DM_TEMP` and mapped over them read-only: clean page cache the kernel drops, where they were anonymous memory only swap could take. `DM_VK_SHADOW_MIN_KB` (256), `DM_VK_SHADOW_AGE_MS` (2000: unwritten that long), `DM_VK_SHADOW_MBPS` (256), `DM_VK_SHADOW_MAX_MB` (6144 on disk), `DM_VK_SHADOW_FREE_MB` (4096 left free), `DM_VK_SHADOW_QUIET_MS` (500: a range a writer touched lately waits), `DM_VK_SHADOW_TICK_RUNS` (64 swaps a present), `DM_VK_SHADOW_MAPS` (40000: no swap past that many mappings), `DM_VK_SHADOW_DIO=0` (buffered writes), `DM_VK_SHADOW_SPARSE=0` (textures only), `DM_VK_SHADOW_DIR` |
| `DM_VK_SPARSE_SPACE_MB=<n>` | start-up (`gfx_vk_budget.c`) | the sparse address space the replay may use instead of the device's `sparseAddressSpaceSize` (4,095 MB on the Adreno 840): to see whether the driver takes more. `DM_VK_SPARSE_PROMO_RESERVE_MB` (1024) leaves that much of it to sparse images in their own format; 0 leaves one R8 and one R16 terrain target of Mario Kart World whole (511 MB) instead of two R8 (682 MB) |
| `DM_VK_PRESSURE_MB=<n>`, `DM_VK_PRESSURE_SWAP_PCT=<p>` | start-up (`gfx_vk_budget.c`) | memory short below n MB of MemAvailable (1536; critical below half) or p % of the swap free (25): scratch blocks kept spare are freed, the shadow file takes its notes without waiting out their age |

| `DM_VK_POOL_PART_MB=<n>`, `DM_VK_POOL_GRANULE_MB=<n>` | start-up | with lazy placement, a pool of n MB or more (1024; 0: none) is placed by parts: the granules (16 MB, from the pool's start) that a range given to the GPU touches become one placed part. | `DM_VK_ZEROCOPY_MAX_MB=<n>` | start-up (first placement) | pools larger than n MB are copied, not zero-copy, and kept whole (unset: no limit). The Legion Y700 2023's gralloc aborts the process allocating a hardware buffer for Unicorn Overlord's 860 MB pool, while its pools up to 250 MB are fine |
| `DM_VK_NO_ZEROCOPY=1` (any value) | at each placement (no comment at the read) | every placement is a copy instead of zero copy: a GPU copy refreshed before each submission (slow, `[RED]` once) |
| `DM_VK_SCRATCH_MB=<n>` | start-up (first scratch block; no comment at the read) | the size of a scratch block (default 8 MB; a larger request gets a block of its own size) |
| `DM_VK_SCRATCH_KEEP_MB=<n>` | start-up (default 16) | the spare scratch blocks a submission slot keeps once the GPU is past it, beyond those its last submission used; the rest are freed (when each slot kept every block it had taken, Mario Kart World 1.8.0 held 394 MB of scratch over the 6 slots at 28 s of its first race) |

| `DM_VK_SPARSE=0` | start-up (`gfx_vk_core.c`) | no sparse-resident images on any device (an A/B): the degraded path, as on a device without them (Mario Kart World's terrain arrays, 1.4 to 5.8 GB each made whole) |

| `DM_VK_SPARSE_UPLOADS=N` | start-up (default 256) | sparse tiles uploaded in one submission (256: 16 MB of its scratch memory); a look that would take more leaves the rest to the next ones |

| `DM_VK_SPARSE_WHOLE_MB=<n>` | start-up (default 512) | on the degraded path, a sparse pool's texture is made whole while it fits; a larger one is not made (it reads as zeros, `[RED]` once) |
| `DM_VK_VT=0\|1\|2` | start-up (`gfx_vk_vt.c`; `tools/shader_vk.py` reads it too, below) | shader-side virtual texturing of the dense images: `0` off (default: a VT bundle draws as before), `1` on (the levels finer than a dense image's first come from a pool of 64 KB tiles that the shaders ask for and the replay uploads), `2` only the dense images' LOD fix (no pool). ## Frame pacing and modes

| Switch | When read | Meaning |
|---|---|---|
| `DM_FPS_PIN=60/40/30` | live | hold that frame-rate step; any other value lets it adapt again |
| `DM_RENDER_SCALE=0.5`-`1.0` | live (every 30 presents) | games with a render-scale stub (Tears of the Kingdom, Breath of the Wild): the 3D views at that fraction of the game's size; 1.0 gives the game's own dynamic resolution back |
| `DM_DYN_SCALE=<lowest scale>` | live | the host's dynamic resolution through the render-scale stub: every 30 frames held at the cap, GPU p90 over 85% of the frame time lowers the scale 0.05, under 70% raises it; 0 = off (scale 1.0). Tears of the Kingdom's pond: 1.0 -> 0.6 saved only 2.6 ms of GPU p90 |
| `DM_ADAPTIVE_FPS=0` | start-up | keep the game's own period |
| `DM_ADAPT_UP_PCT=<p>` | start-up (`perf_android.c`; default 90, 1-99) | the percentile of frame work the adaptive rate judges for a step up. At the longer period the clocks drop and the work grows: Unicorn Overlord's opening, once stepped down to 40 fps, never went back up at 90. With 50 it tries the shorter period again; a try that misses the display steps back down, and the next waits twice as long |
| `DM_FSTEP_PROBE_RAMP=0` | start-up (`gfx_common.c`) | off: the frame step's probe no longer keeps its grace while its frames get cheaper (`gfx/nvn/hle_nvn.c` `g_fs.ramp`). On by default, as on the Mac: mobile GPU clocks ramp over seconds too |
| `DM_VK_PACE=0` | live (every 30 presents, `gfx_vk_present.c` `pace_desired`) | present without desired times (`VK_GOOGLE_display_timing`): frames go out at the first vsync after they are latched, as before. | `DM_VK_UPSCALE=fsr\|bilinear\|off` | live (every 30 presents, `gfx_vk_fsr.c`) | how the game's crop reaches the swapchain image. `fsr` (default): FSR 1, EASU into an intermediate image of the picture's size (A2B10G10R10), then RCAS into the swapchain image, the overlay in the same pass; `bilinear`: one bilinear draw; `off`: the old path (a clear of the whole image, `vkCmdBlitImage`, the overlay in a pass of its own), also taken on a device without dynamic rendering. | `DM_VK_FSR_FP16=0` | start-up | the 32-bit shaders where the device has `shaderFloat16` (the 16-bit ones are the default there; a device without it takes the 32-bit ones) |
| `DM_VK_FSR_TIME=0` | start-up | no present GPU timer. | `DM_VK_NDSR=fsr\|game` | live (every 64 dispatches, `gfx_vk_fsr.c` `vk_ndsr_wanted`; the hook is in `gfx_vk_exec.c` `dispatch`) | a game's own upscaler, agl's NDSR network (the compute shaders the shader map found in `agl_ndsr.pck`: `DM_GAME_UPSCALER_KEYS`). `fsr` (default): its dispatch drawn by FSR 1's EASU from its input rectangle into its output rectangle (push bank 24), in the variant's colour read from its SPIR-V (linear input encoded as read; output encoded, linear clamped to 1, or linear up to 128), before its pipeline is ever made; the network's emulated tensor code costs tens of ms on Adreno and its pipelines are made on the replay thread at first use. | `DM_VK_PRETRANSFORM=1` | live (every 30 presents, `gfx_vk_present.c`) | pre-rotation, off by default until a run has checked it on screen: where the display is turned from its natural orientation (`[vk] surface: transform now 0x2 …` at each swapchain; `present: VK_SUBOPTIMAL_KHR` counts the presents the compositor turns), the swapchain is made in the display's transform and the picture and the overlay are drawn turned (`swapchain … pre-rotated 90`). | `DM_MOVIE_AUDIO_SLOTS=N` | first audio decoder (`host/hle_movie.c`) | profile env: fewer output slots for the movie library's audio decoders than 64 (4..63), for a player that keeps the outputs it acquires in a fixed ring (Mario vs. Donkey Kong's ring holds 32) |
| `DM_NO_ADPF=1` | start-up | no Android performance hints |

| `DM_OPMODE=0/1` | start-up (`host/hle_oe.c`) | handheld / docked at launch. The pause menu's Mode setting (`docked=` in `settings.txt`) overrides it and switches live |
| `DM_AUDIO=0` | start-up (`host/hle_audio.c`) | silent sink (Android defaults to real output) |
| `DM_SHAKE_G=1.5` | start-up (`android/front_android.c`) | how hard (in G beyond gravity, 1.5 by default) the device must be shaken for the controller's six-axis sensor to be shaken (`DM_BTN_SHAKE`, `host/hle_hid.c`; Super Mario Odyssey's cap throw). Each detected shake logs `front end: device shaken (peak … G)`; `ctl.txt` `Shake~0.4` shakes it without the device |
| `DM_TOUCH_DOCKED=screen` | first touch read (`host/hle_touch.c`) | profile env: docked touch points as a game that takes the panel's values as screen pixels expects them (Unity 2019.4: x = screen column, y = screen row − 360 on 1920x1080). On Android touches reach the game in both modes (`hle_hid.c` `touch_on`); a Switch has no docked touch |

## Paths the app sets

`front_android.c` sets these at launch, before it reads `env.txt`, so a line there replaces them.

| Switch | When read | What it does |
|---|---|---|
| `DM_ROOT` | at each use | the files folder (external, else internal): the backend's files go there, among them the pipeline cache `vk_pipeline_cache.bin`, the prewarm list `vk_pipelines.bin`, `captured_shaders/`, the pass dumps `pass_NN.ppm`, the `DM_NVN_SHDUMP` files, the frame shots without `DM_VK_SHOT_DIR`, and the shader bundle without `DM_VK_SHADERS` |
| `DM_VK_SHADERS=<path>` | once, when the bundle is first opened (`gfx_vk_shader.c`) | the shader bundle (`<files>/shaders.dmsv`): another bundle is the A/B of a translation switch below |
| `DM_SAVE=<dir>` | at start-up (`saves_android.c`) | the game's committed save (`<internal data>/save`), and `<DM_SAVE>_device` when the game mounts a device save too: what the save manager exports and imports |

## Shader translation (`tools/shader_vk.py`)

Read by `tools/shader_vk.py` from its environment when it builds the shader bundle (`shaders.dmsv`), not on the device. For the flags, any value but empty or `0` turns them on. They are part of the bundle's reuse key (`porter/pipeline.py` `SHADER_SWITCHES`), so changing one rebuilds the bundle at the next port; a profile's `env DM_VK_VT=<non-zero>` builds it with `--vt`.

| Switch | When read | Default and meaning |
|---|---|---|
| `DM_SHADER_SPILL_KEEP=<bytes>` | bundle build | compute shaders whose shared memory is past the device's limit (Mario Kart World's 168 of 48 KB) keep their first bytes in workgroup memory and the rest in the spill buffer's slice, each access testing its word; `32768` keeps the device's whole limit (MKW: a dispatch's first 682 records never touch the buffer, 8 MB instead of 24). Default 0: all in the buffer, as before; not yet run on a device |
| `DM_SHADER_NAN_MINMAX=1` | bundle build | float min / max / clamp as NMin / NMax / NClamp (Maxwell's FMNMX: a NaN operand gives the other operand, `.SAT` gives 0) instead of FMin / FMax / FClamp, which leave a NaN's result to the device. Default 0 until a device run shows what the Adreno compiler makes of them (Mario Kart World 1.8.0: 232,000 in its pixel shaders) |
| `DM_SHADER_SPIRV_OPT=1` | bundle build | `spirv-opt -O` over each module, every binding and interface variable kept (a module it fails on, or whose result does not validate, stays as translated). Off by default, not measured on a device: on Mario Kart World 1.8.0 it took out 52% of the vertex and pixel shaders' instructions, mostly what a driver's own SSA construction removes too, leaving 7.5% fewer arithmetic, extended and sampling instructions, and compute shaders grew 21% |
| `DM_SHADER_WIDE_WORDS=1` | bundle build | the words of a wide storage load or store (Ampere's LDG / STG .64 / .128) take one word index plus j, so a driver can see they are neighbours and read them whole. Default 0 (each word its own index) until a device run shows Adreno's compiler merging them |
| `DM_SHADER_HMMA_F16=1` | bundle build | agl's NDSR upscaler network: the HMMA helper in packed half arithmetic (no conversion of A and B, sums in half precision; the device needs `shaderFloat16`) instead of float. Default 0 keeps the float sum: the half sum is not bit-exact |
| `DM_SHADER_DRAW_PARAMS=0` | bundle build | vertex shaders read the draw's base vertex, base instance and draw index from c0 (+ 0x640, 0x644, 0x648), as before, not from Vulkan's `BaseVertex`, `BaseInstance` and `DrawIndex` (the default): the replay puts 0 there for an indirect draw, whose record the GPU writes (Mario Kart World's GPU-culled vegetation came and went from frame to frame) |
| `DM_VK_VT=1` | bundle build | the default of `--vt`: fragment shaders sample their candidate 2D arrays through `vt_sample` / `vt_qlod` (the replay side: `DM_VK_VT` under Memory) |

## Control file lines (`ctl.txt`)
- **Buttons:** `A`, `B`, `X`, `Y`, `L`, `R`, `ZL`, `ZR`, `Plus`, `Minus`, `Up`, `Down`, `Left`, `Right`, `LS`, `RS`.
- **Sticks:** `LUp`, `LDown`, `LLeft`, `LRight` (same for `R…`).
- **Hold and combine:** `~seconds` sets the hold (default 0.15), e.g. `A~0.2`. `+` combines keys.
- **Touch:** `T<x>x<y>` taps a normalized point.
- **Motion:** `Shake` shakes player 1's controller (its six-axis sensor) for the hold, at least one whole shake.
- **Other lines:** `env KEY=VALUE`, `shot <path>`, `passdump <n>`, `drag x0 y0 x1 y1 [s]`. A line starting with `#` is ignored.
- **Delays:** an unknown key name logs `[RED]` but still waits its hold, so `none~0.1` works as a delay between lines.
- **Replay:** the reader starts at the file's end when the app launches; lines from earlier runs are never replayed.
